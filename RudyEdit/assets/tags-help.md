# Tags.xml reference

Tags.xml stores all file tag names in the same configuration folder as Config.cs and KeyboardShortcuts.xml. Back it up with tagged documents.

Example (use a real file identifier generated by RudyEdit):
```xml
<Tags Version="1">
  <File Id="fa0f8e2e-d9cc-4561-b020-6a3b2bd16f41" Path="/home/user/notes.md">
    <Tag>work</Tag>
    <Tag>planning</Tag>
  </File>
</Tags>
```

The UUID matches the hidden rudyedit-id comment in the text file. The Path attribute is informational; search uses the identifier, so renaming or moving a document preserves its association. Save As creates an independent identifier. Tag names are XML escaped; for example, a&b is written a&amp;b. Duplicate identifiers, unknown schema versions, and DTDs are rejected. Keep this file's existing records when editing it manually.

Ctrl+Shift+T toggles the Text-mode tag bar. Ctrl+Alt+T shows it and focuses Add tags. Enter adds comma-separated tags, Ctrl+S commits them to Tags.xml and saves the file link, and Escape returns to the document. Ctrl+Alt+G searches saved files by tags. ShowTagBar = false; in Config.cs hides the bar at startup.

Existing leading tags comments migrate on the next save after opening. The identifier is hidden in RudyEdit and Markdown renderers; raw file tools can display the comment. A copied document needs the corresponding Tags.xml to recover its tag names. Missing registry entries display no tags. XML changes made by another editor are detected before overwriting tags; reopen the document to load them. Unsaved changes are not written to the registry.
